2. PARTS OF THE WORK: WHAT WAS TAKEN AS IT WAS, WHAT WAS CHANGED AND WHY
-------------------------------------------------------------------------
A. Lexer:
   - What was taken as it was: The byte-level state-machine lexer architecture, UTF-8 2-byte Cyrillic character handling (`lexchar::isCyrillicLead`, `lexchar::isContinuation`), and token classification from Stage 1.
   - What was changed and why:
     * Added `kw::FACT = "факт"` to keywords table to support global constant declarations.
     * Implemented `CommentState` (`src/states/comment_state.h`) and hooked it into `StartState` on encountering `#`. Discards characters until newline (`\n` or `\r\n`), leaving line/column character calculations intact. String literal `#` remains literal.

B. Parser & AST:
   - What was taken as it was: Recursive-descent parser structure (one method per grammar rule) and AST node hierarchy.
   - What was changed and why:
     * Added `GlobalDeclNode` (`src/nodes/global_decl_node.h`) inheriting from `DeclNode`.
     * Added `parse_global_decl()` and `parse_const_expression()` (arithmetic `+ - *`, equality `== !=`, negation `!`, literals, earlier constant identifiers).
     * Updated `parse_program()` to parse `{ global_decl } { struct } { fn } body`.
     * Updated `parse_body()` to enforce Rule P2: every body (program body, function body, member function body) must end with an exit statement (`чайна_перерва`). Earlier exit statements are permitted anywhere.

C. Semantic Analysis:
   - What was taken as it was: The two-pass symbol collection architecture and basic type-checking framework.
   - What was changed and why:
     * Implemented global constant registration pre-pass with compile-time expression evaluation (`fold_const_expr`) and strict signed integer overflow checking using compiler built-ins (`__builtin_add_overflow`, `__builtin_sub_overflow`, `__builtin_mul_overflow`) for `i32` and `i64` (Rule C2).
     * Enforced single shared namespace across global constants, structs, and top-level functions (Rule C5).
     * Enforced Rule N2: function bodies cannot access program-level local variables.
     * Implemented Rule N3 lookup hierarchy in member functions: `local/param -> struct field -> global constant`.
     * Enforced Rule N6: locals, parameters, and fields cannot shadow structure or function names.
     * Implemented Rule P3 unreachable code detection: statements after an exit statement are still type-checked, emitting `warning: line L:C: unreachable code` to stderr once per body/block, allowing compilation to succeed with exit code 0.
     * Enforced mutability rules: verifying assignment chains (`all_fields_mut`) and prohibiting mutating member calls on constant objects.

D. Code Generation:
   - What was taken as it was: Code generation visitor using `llvm::IRBuilder<>`.
   - What was changed and why:
     * Global constants emit `llvm::ConstantInt` directly upon use (in `visit_var`), avoiding any heap allocations or loads.
     * Early exit termination: `CodeGen` immediately terminates basic block emission after an exit statement in a statement list, avoiding unreachable or malformed LLVM IR.
     * Function prefixes (`tea_fn_...`) preventing collisions with C runtime names (`main`, `printf`, `scanf`).
     * Identified `llvm::StructType` definitions with field access via `CreateStructGEP` by numeric index from symbol table.

E. Tests & Test Runner:
   - What was taken as it was: Stage 1 test runner foundation.
   - What was changed and why:
     * Updated existing Stage 1 tests to comply with Rule P2 (appended `чайна_перерва 0`).
     * Intentionally deleted obsolete tests: `tests/ok/empty_program` (violates P2) and `tests/err/lex_invalid_char_hash_in_if` (`#` is now a valid comment).
     * Extended `run.sh` to run end-to-end tests through `lli`, feeding `.in` standard input files, comparing `.expected` stdout, and verifying `.warn` stderr.
     * Added comprehensive test suite: 46 ok tests, 11 e2e tests, 61 err tests (118 tests total, all passing).

3. WHAT WAS UNDERSTOOD
----------------------
In this stage, the compiler evolved from a simple linear script interpreter into a full-fledged language compiler targeting LLVM IR.
Key concepts understood:
1. LLVM IRBuilder Code Generation: Instead of manually building LLVM IR text via string formatting (which is prone to syntax and type mismatch bugs), `llvm::IRBuilder` provides type-safe IR generation with SSA values, basic blocks, and verification. Forward declarations of functions and structures allow mutually recursive and forward-referenced calls.
2. Two-Pass Semantic Analysis & Symbol Tables: Compiling functions and structures requires resolving identifiers before all bodies are parsed. A signature pre-pass registers types, fields, and function prototypes, while the second pass analyzes function bodies with scoped symbol tables.
3. Constant Folding & Integer Overflow: Evaluating constant expressions at compile time requires strict type checking and bit-width overflow detection (`i32` vs `i64`), ensuring runtime constants are statically validated.
4. Struct Layout & Object Memory: Structures are mapped to LLVM identified struct types. Struct fields are accessed via GEP (GetElementPtr) by index, derived from the semantic symbol table rather than name lookups at runtime. Member functions are compiled as regular functions with an implicit pointer (`this`) as parameter 0.
5. Exit Control Flow & Unreachable Code: Allowing `чайна_перерва` anywhere while mandating a final exit requires treating exits as control flow terminators while maintaining semantic checks on dead code and cleanly terminating LLVM basic blocks.
