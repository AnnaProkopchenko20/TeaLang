2. COMPREHENSIVE BREAKDOWN OF AI ASSISTANCE (WHAT WAS TAKEN, CHANGED, AND WHY)
--------------------------------------------------------------------------------

A. Syntax Design & Language Extensions (Task 1: Threads & Loops)
   - What was provided by AI:
     * Proposed grammar additions (EBNF) and keyword candidates fitting the Ukrainian tea-themed domain.
     * Evaluated handle semantics (`потік`), thread spawning syntax (`витечи fn(args) => handle`), join syntax (`дочекатись handle`), range loop syntax (`для (init; cond; step)`), and screen clearing statement (`clear()`).
   - What was changed and why:
     * Selected `потік` as a dedicated non-copyable handle type to isolate thread state from regular integer primitives.
     * Enforced strict parameter passing rules: arguments are evaluated in the spawning thread, packed into a heap payload (`malloc`), and passed to a generated C-compatible wrapper function matching `void* (*)(void*)`.
     * Established explicit data race policy: unsynchronized concurrent writes to shared variables lead to undefined behavior, documented clearly in `README.md`.

B. AST Optimizer Architecture (Task 2: Transformations & Effect Oracle)
   - What was provided by AI:
     * Architectural design of `WalkVisitor` base class in C++ to handle default traversal across 23 AST node types without boilerplate.
     * Implementation of `EffectOracle` using call-graph fixpoint iteration to classify pure vs. effectful functions (accounting for `print`, `read()`, `while` loops, mutating member functions, and transitively called effectful routines).
     * Dead Code Elimination algorithms: `var_remover` (unused variable declaration and side-effect-free assignment removal) and `fn_remover` (unreferenced top-level function pruning).
     * Single-call non-recursive function inlining (`inliner.cpp` & `cloner` helper): parameter substitution via local allocas, variable name mangling (`_inlineN`), control-flow boundary checks (bypassing functions with early `чайна_перерва` exits inside `якщо`/`допоки`), and call-site expression replacement.
   - What was changed and why:
     * Preserved side-effecting initializers (e.g., declarations with `read()` or function calls) during variable pruning by converting them into effectful statement calls.
     * Restricted inlining to single-call non-recursive functions with clean tail exits to prevent invalid control-flow flattening.

4. HUMAN COMPREHENSION, VERIFICATION & LEARNING OUTCOMES
---------------------------------------------------------
Through active collaboration with AI tools and rigorous local validation, the following core compiler engineering concepts were understood, verified, and mastered:

1. POSIX Thread Lowering in LLVM IR:
   - Multi-argument function calls spawned on background threads cannot pass stack values directly to `pthread_create`. They must evaluate arguments in the caller thread, pack them into a heap-allocated memory buffer (`malloc`), and pass the pointer to a generated static worker wrapper function with signature `void* (*)(void*)`.
   - Thread handles must be managed safely to prevent double-joining or premature deallocation.

2. AST-Level Transformations vs. IR-Level Optimization:
   - Performing variable DCE and function inlining at the AST level before IR lowering preserves domain semantics, type safety, and symbol table visibility.
   - Building a global call graph fixpoint (`EffectOracle`) is necessary to distinguish pure functions from effectful ones (I/O, recursion, mutation, loops) before deleting unused variable assignments.

3. Position-Independent Code (PIC) & Native Linking:
   - Translating LLVM assembly (`.ll`) to native binaries on modern 64-bit Linux environments requires setting relocation models (`llc -relocation-model=pic`) to adhere to Position Independent Executable (PIE) standards and linking against `-pthread`.
